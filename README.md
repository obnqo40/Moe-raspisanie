# Моё Расписание — образовательный V1-прототип

Веб-приложение демонстрирует управление школьным расписанием: просмотр и редактирование уроков, справочник преподавателей, генерацию расписания, импорт/экспорт Excel и базовые PWA-возможности.

## Project Status

Это исходный клиентский прототип V1, сохранённый как учебная демонстрация продукта. Он не предназначен для хранения реальных учётных данных, персональных данных учеников/преподавателей или иной чувствительной информации.

- Расписание и демонстрационные профили хранятся только локально в браузере (IndexedDB/localStorage).
- Привилегированная синхронизация с GitHub и удалённая запись пользователей отключены.
- Вход и роли в V1 демонстрируют интерфейсные сценарии, но не образуют доверенную границу безопасности.
- Сервер-авторитетная версия V2 запланирована, но в этом репозитории ещё не реализована.

Используйте только вымышленные данные и уникальные демонстрационные пароли, которые нигде больше не применяются.

## Функциональность V1

- локальная демонстрационная регистрация и вход;
- роли «ученик» и «учитель» для показа разных элементов интерфейса;
- просмотр, добавление, редактирование и удаление уроков;
- генератор расписания;
- импорт и экспорт Excel (`.xlsx`);
- локальное хранение расписания в IndexedDB;
- PWA-оболочка и офлайн-кэш статических ресурсов.

## Запуск

Для корректной работы IndexedDB и service worker запустите каталог через простой локальный HTTP-сервер. Например, если установлен Python:

```text
python -m http.server 8000
```

Затем откройте `http://localhost:8000`. Установка зависимостей не требуется.

## Security Limitations of V1

- Состояние, находящееся только в браузере, можно изменить вручную; поэтому клиентские роли не обеспечивают настоящую авторизацию.
- Локальная демонстрационная проверка пароля не заменяет серверную аутентификацию и не должна использоваться с реальными паролями.
- Хранение привилегированных API/GitHub-ключей в браузере было архитектурной ошибкой; поля, storage-ключи и сетевые пути для такой синхронизации удалены из публичной версии.
- Публичные наборы пользователей не должны содержать реальные личности, пароли или производные от паролей. `users.json` намеренно пуст.
- Серверная аутентификация, авторизация и постоянное хранилище относятся к V2.

Эндпоинт `api/users.js` оставлен только для явного ответа о том, что удалённая запись отключена. `api/users.json.js` возвращает пустой список для совместимости и не обращается к GitHub.

## V2 Direction (planned)

Планируемая, но пока не реализованная архитектура:

```text
Browser
  ↓
Authenticated backend API
  ↓
PostgreSQL
```

V2 должна включать:

- серверные сессии/аутентификацию;
- серверную авторизацию для всех операций;
- сильное хеширование паролей, если пароли останутся способом входа;
- проверку и нормализацию API-запросов;
- пользователей и роли, принадлежащие базе данных;
- отсутствие привилегированного GitHub PAT или иного серверного секрета в browser storage.

До реализации V2 этот проект следует считать только локальной образовательной демонстрацией.
